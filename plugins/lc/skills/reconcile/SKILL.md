---
name: reconcile
description: Re-check this project's open stories against the actual repo and correct the board
argument-hint: [epic or story-id range, optional]
---

Verify the backlog against reality. Stories drift as the code moves, and some may have been true the day they were written.

1. Read `.claude/launch-control.json` and query **`views.open`** in **view mode**, every page until `has_more` is false: this project's stories that are not Done, which is all this command audits. Do not read `views.road`: it also holds every Done story, so it grows with the project's history. If the config has **no `views.open`** (a board provisioned before 0.14.0), say that `/lc:doctor` names the view to create, and read `views.road` for now. Every project has its own open and road views, scoped to that project. Never substitute a shared browse view — its filters are editable in the board UI and a stray filter silently returns another project's rows, or none.
2. **Sanity-check what came back before doing anything with it.** If any returned **Story ID** does not start with this repo's prefix, or any row is `Done`, the view is misconfigured — say so and stop. If zero rows came back, do not report "nothing to reconcile" on that alone: an empty result from a scoping bug reads exactly like a clean bill of health, and that is the failure this command exists to catch. Run `/lc:doctor`, which reads the road to the end and fails an empty one; only once it is clean is an empty open view a project with nothing left open.
3. Take every story whose **Agent can do this** is checked. If the user gave an argument, narrow to it. Cap the run at about 15 stories and say which you covered — a partial honest pass beats a rushed complete one.
4. For each, read its **Done when** and go and check it **in the repo**. Actually run the command, read the file, check the setting. Do not infer from a doc, and do not infer from the story's own Notes field — that is what is being audited.
5. Classify each:
   - **Already true** — set Status to `Done` and write into **Last session**: today's date, "reconciled", and the specific evidence (the command you ran and its output, or the file and line). Evidence is required; a bare "already done" is not acceptable.
   - **Still open, unchanged** — leave it.
   - **Drifted** — the criteria are now wrong, or the trap it warns about no longer exists, or it needs different steps. Update **Done when** and **Notes and traps**, and say what changed and why.
   - **Obsolete** — the work no longer makes sense. Do NOT delete it. Set Status to `Done` and record in **Last session** why it is moot.
6. If anything flipped to Done, check whether it unblocks others: **read the shared `dependents` view (`views.dependents`) in view mode** - every project's stories that are not Done and name a blocker, which is every row that could be waiting on this one. It is board-wide, because a dependent can live in another project (a clock blocks stories across projects), so the project's own views would miss it; and it leaves out Done rows, so it does not grow with the board's history. If the config has **no `views.dependents`** (a board provisioned before 0.14.0), say that `/lc:doctor` names the view to create, and read the shared `board` view for now. Read it once, after the last flip, not once per story. Page it to the end with `start_cursor` until `has_more` is false, then `python3 <base directory>/../doctor/ids.py dependents <page files...> --url <that story's page URL>` lists the dependents. Each page the tool saved to a file is passed by its path. A page that came back inline - the last one usually does - is **not** written to a file: give it on the command line as `--inline-page <rows on that page> <its has_more, true or false> --row <Story ID> <Status> <page url> <Blocked by URLs comma-separated, or ->` with one `--row` per row, in order (`-` for a blank Story ID). Those are short values you can state exactly; the script checks the count and every URL, and refuses rather than answers when one is off. Never read the rows by eye, and never use a rows-mode or SQL query here: Notion's free plan meters both from one allowance, and this runs on every reconcile that closes something. If `/lc:doctor` reports the view's filter wrong, fix that first - a wrongly filtered view silently drops dependents. For each dependent, fetch its blockers; if all are now Done and it is in `Backlog`, promote it to `Ready`.
7. Report a short table: story ID, verdict, evidence. Then state how many launch blockers this project actually has left.

Be sceptical in both directions. Marking something Done that is not is worse than leaving it open — it removes the only thing that would have caught the gap before submission.
